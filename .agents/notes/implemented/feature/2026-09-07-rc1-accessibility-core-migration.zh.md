# Agent Note：RC.1 无障碍核心迁移

状态：已实现

[English](2026-09-07-rc1-accessibility-core-migration.md) | 中文

## 问题

无障碍候选版本及其自动化浏览器证据基于 `dsh-v0.1.2-alpha.2`。DSH `0.1.2-rc.1` 修改了 Session 遍历、视图选择、浏览器夹具、生成快照和 CI，并删除了过时的 SQLite 包。因此，复用 alpha.2 证据会把未经测试的代码错误地声明为已覆盖，而只做文本合并则会丢失当前 RC 行为，或静默削弱焦点和键盘交互契约。

## 决策

无障碍核心从官方精确标签 `dsh-v0.1.2-rc.1` 出发，按交互所有者迁移。Session 事件模型、活动视图解析、当前文案、浏览器夹具行为及已删除包均以 RC.1 为准。无障碍分支保留原生语义、焦点约束与恢复、键盘复合控件模式、实时播报、稳定的 headless 文本与 JSON 输出、环境无障碍检查及版本化浏览器证据。

迁移后的浏览器期望值由组装完成的 RC.1 应用重新生成。聚焦测试覆盖 headless 输出、Session 投影、CI 证据契约及受影响的客户端所有者。干净且已提交的候选版本会在 Chromium、Firefox 和 WebKit 中运行 P0 无障碍套件；证据记录精确提交，并把不受支持的 forced-colors 模拟记为能力限制，而不是通过。

Node 24.3 开发监听器继续使用 `unrun` 来完整加载工作区配置图；RC.1 构建仍走常规 tsdown 路径。解决已删除 SQLite 包的合并冲突后不能遗留空目录，否则工作区 glob 会把它当成包，并错误地应用根入口模式。

## 考虑过的替代方案

**继续把 alpha.2 作为无障碍版本。** 否决，因为它缺少当前 RC 产品变化，并会针对过时的软件包线作兼容性声明。

**不重新构建 RC.1，直接复制 alpha.2 快照和测试。** 否决，因为生成期望值是组装后产品形态的证据，不是可直接移植的源代码资产。

**把必需语义移到配套插件。** 否决，因为插件无法在渲染后可靠重建组件拥有的焦点、状态、嵌套对话框、虚拟化导航和持久 Session 边界。

## 后果

分叉仓库现在具备基于 RC.1 的无障碍候选版本，可从干净的精确修订重现其自动化 P0 浏览器证据。配套仓库只有在固定该修订并通过自身检查后，才可声明兼容 RC.1。自动化浏览器、DOM、几何、对比度、动效和 headless 证据仍不能证明 VoiceOver、NVDA、盲文、开关输入或残障开发者任务完成情况；这些证据行在真实参与者提交前保持开放。
