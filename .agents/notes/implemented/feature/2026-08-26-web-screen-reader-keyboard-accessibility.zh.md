# Agent Note: Web 读屏与键盘无障碍的职责归属

Status: implemented

[English](2026-08-26-web-screen-reader-keyboard-accessibility.md) | 中文

## Problem

Web 客户端为若干控件暴露了 ARIA role，却没有完成这些 role 所承诺的交互契约。会话树没有键盘入口和漫游导航，模态弹窗既不约束焦点也不恢复焦点，关闭搜索可能把焦点遗留在不可见输入框上，布局缩放把手只能用指针操作，页面缺少稳定地标，对话既没有具名日志，也没有有界的完成播报。第三方插件可以观察并重写渲染后的 DOM，但哈希类名、组件重挂载、嵌套弹窗与私有状态使这种方案无法保持正确的职责归属与时序。

## Decision

无障碍行为由拥有对应交互的核心组件负责。`Modal` 维护打开弹窗的栈，使应用根节点进入 inert 状态，选择初始焦点，约束 Tab 遍历，只允许最上层弹窗响应 Escape 与遮罩关闭，并把焦点还给打开它的控件。设置面板和原图灯箱都使用这个基础组件，不再各自维护弹窗实现。

工作区树、扁平会话树与搜索结果树共用同一个漫游焦点键盘控制器。一个树节点及其自有操作进入 Tab 顺序；上／下方向键与 Home／End 在已渲染行之间移动，右／左方向键操作工作区展开、收起与父级移动，Enter／空格激活当前行。搜索框通过 Escape 或明确清除关闭时把焦点还给持续存在的搜索按钮；由外部指针触发的关闭不会覆盖读者的新目标。

共享 `Menu` 基础组件和模型选择器实现菜单按钮模式，而不是把每个菜单项都变成独立的 Tab 停靠点。上／下方向键从对应边缘打开菜单，方向键、Home／End 与前缀输入在同层移动，右／左方向键进入与退出子菜单，Escape 关闭当前层或整个菜单，关闭后焦点返回触发控件。命令建议输入框暴露具名 combobox、其控制的 listbox 和当前 active descendant。JSON 检查器与子智能体层级都是采用漫游焦点的真实 tree：叶节点加入同一复合控件，右／左方向键遍历层级，层级触发器也可以脱离悬停直接激活。

用户问题选项使用具名 radiogroup 和唯一的漫游 radio；方向键与 Home／End 更改当前答案；自定义答案文本框的可访问名称包含所属问题。反馈备注在前后两个 Tab 边界都保持弹层式焦点职责，而指针关闭不会夺回用户新选择的焦点。Trajectory 时间线是支持多选的 listbox，具备 active-descendant 浏览、Shift 扩展范围、全选、清除和打开记录；其台账表格只让一个数据行进入顺序 Tab，并支持方向键与边界键导航。

外壳把对话列渲染成 `main`，把侧边栏与详情面板渲染成具名 complementary 地标，并把两个布局分隔条渲染成具名、可聚焦、携带数值元数据的垂直 separator，支持左右方向键与 Home／End 调整。消息输入框始终拥有本地化的可访问名称。对话提供具名 `log`，但不把流式变化设为 live；用户与智能体行使用具名 article；运行中的轮次转为空闲时挂载一次 polite 状态播报，而不会朗读每个 token 或工具增量。

会话视图与 Trajectory 检查器的标签列表只保留一个漫游 Tab 停靠点，使用左／右方向键与 Home／End 激活标签，标签列表有名称，并与 tab panel 显式关联。Trajectory 详情分隔条暴露范围元数据、可见的键盘焦点、小步与 Shift 大步调整及边界键。上下文占用率是控制具名信息 region 的 disclosure，不是抢占焦点的 dialog。

可选 companion 插件通过已声明 slot 提供说明、诊断、偏好或其他增量 UI，不通过 DOM 变更修复核心语义。这遵循 [slot 组合决策](../architecture/2026-07-22-slot-type-chain-implementation.zh.md)：替换级行为留在拥有该 slot 的组件中，增量功能注册进已声明的子 slot。

## Assistive-technology contract

VoiceOver、NVDA 与 JAWS 用户通过 Tab 进入会话树，再用普通方向键在复合行中导航。弹窗只提供一个模态焦点范围，并在关闭后返回其触发控件。对话流可通过结构导航阅读，不产生逐 token 语音；完成状态是提示智能体新输出可供阅读的有界信号。指针缩放与键盘缩放更新同一份带限幅的布局偏好。

## Alternatives considered

**仅用插件提供 MutationObserver 适配。** 拒绝，因为它需要从不稳定 DOM 推断职责，与 React 提交竞争，重复组件状态，也无法安全实现嵌套焦点恢复或权威的展开状态变更。

**让每个树节点都成为独立 Tab 停靠点。** 拒绝，因为长会话列表会占据顺序导航，并且与复合 `tree` role 冲突。漫游焦点只保留一个 Tab 停靠点，同时让当前节点自有的操作按钮继续可用。

**在流式消息日志上使用 `aria-live="polite"`。** 拒绝，因为 token 与工具更新会持续打断语音。日志保持具名结构但关闭 live 更新，独立状态只报告从运行到空闲的转换。

**让设置弹窗继续独立于 `Modal`。** 拒绝，因为两套弹窗实现在嵌套、背景 inert、Tab 约束和焦点返回上会发生漂移。共享基础组件只实现一次契约。

## Testing

组件测试固定弹窗栈、焦点约束、背景 inert、焦点返回（包括原图灯箱）、菜单与前缀输入导航、combobox 所属关系、树形漫游按键与展开、单选组导航、反馈弹层边界遍历、时间线范围选择、台账行导航、搜索焦点返回、地标、分隔条元数据与缩放、漫游标签列表与 tab-panel 关联、disclosure region、输入框名称、消息日志名称、article 名称和完成转换。组装后的浏览器回放继续作为语义输出与真实浏览器焦点行为的产品级检查；人工 VoiceOver 回归覆盖 jsdom 不实现的原生无障碍树与按键路由。可选的 `dsh-accessibility` companion 会检查 14 项结构契约并提供操作指引；检查全部通过是回归信号，不等同于辅助技术认证。

## Consequences

核心组件承担了更多显式焦点与键盘状态，共享基础组件必须处理嵌套职责，不能把每个实例视为彼此独立。作为回报，无障碍语义与视觉交互使用同一生命周期和状态权威，无需可选包即可工作，也能脱离展示层选择器进行测试。增量无障碍插件仍适合提供说明和诊断，但不能声称让未修补的核心完全无障碍。
